# 修复 ESP32-S31 高采样率 I2S 时钟配置失败

## Context（背景）

用户贴出的实机日志（18:21:19，track=4 `/sdcard/MUSIC/Craig David - 7 Days.flac`）显示 96kHz FLAC 曲目播放时音频链路起不来：

```
I (17516) I2S: Music I2S DMA档：desc=26 frames=256
E (17516) i2s_std: i2s_std_calculate_clock(76): sample rate is too large
E (17516) i2s_std: i2s_std_set_clock(100): clock calculate failed
E (17526) i2s_std: i2s_channel_init_std_mode(341): initialize channel failed while setting clock
E (17536) I2S: 初始化 I2S 标准模式失败：ESP_ERR_INVALID_ARG
```

### 已确认的根因

- `src/drivers/audio/i2s_output.c:65-83` 使用 `I2S_STD_CLK_DEFAULT_CONFIG(sample_rate_hz)`，未显式指定时钟源，`mclk_multiple` 为默认 256。
- ESP32-S31 的 `soc/clk_tree_defs.h:542` 定义 `I2S_CLK_SRC_DEFAULT = SOC_MOD_CLK_XTAL`，即 XTAL 40MHz。
- `esp_driver_i2s/i2s_std.c:68,76` 的约束：`sclk > 1.99 * mclk`，其中 `mclk = rate * mclk_multiple = rate * 256`。
  - 换算：`40MHz > 1.99 × rate × 256` → `rate < 78.4kHz`。
  - 因此 44.1k/48k/32k 正常，而 **88.2k / 96k / 176.4k / 192k 必然失败**（96k 已由日志证实，`desc=26` 对应 `audio_rate_profile.h` 的 96000U 档）。
- S31 的 I2S 可选时钟源（`soc/clk_tree_defs.h:535`）：`SOC_MOD_CLK_XTAL`、`SOC_MOD_CLK_APLL`、`SOC_MOD_CLK_RC_FAST`、`EXTERNAL`；**没有 `PLL_F160M`**，所以不能照搬 P4 的写法。
- APLL 路径由驱动自动定频（`i2s_common.c:746-772`）：`mclk_div = max(2, ceil(5.303031MHz/mclk)+1)`，`apll_freq = mclk * mclk_div`，上限 125MHz（`hal/esp32s31/include/hal/clk_tree_ll.h:57`）。
  - 96kHz：mclk=24.576MHz → APLL 49.152MHz ✓
  - 176.4kHz：mclk=45.1584MHz → APLL 90.3168MHz ✓
  - 192kHz：mclk=49.152MHz → APLL 98.304MHz ✓
  - 三者均低于 125MHz 上限，且 `mclk_div=2` 满足 `sclk > 1.99*mclk`。

## 修改方案（推荐）

只改 `src/drivers/audio/i2s_output.c`，在 `i2s_output_create_channel()` 中按采样率选择时钟源：**低采样率保持现有 XTAL 路径不变（已实机验证 44.1/48k），仅当 XTAL 无法满足约束时切 APLL**。

### 具体改动

1. 新增一个静态判断函数（放在 `i2s_output_create_channel` 之前），逻辑为：

```c
// XTAL 作为 I2S 源时钟时必须满足 sclk > 1.99 * mclk(rate * 256)，
// 高采样率下 40MHz XTAL 不足，需要改用 APLL。
static bool i2s_output_should_use_apll(uint32_t sample_rate_hz)
{
    uint64_t mclk_hz = (uint64_t)sample_rate_hz * I2S_MCLK_MULTIPLE_256;
    uint32_t xtal_hz = 0;
    esp_err_t ret = esp_clk_tree_src_get_freq_hz(
        SOC_MOD_CLK_XTAL, ESP_CLK_TREE_SRC_FREQ_PRECISION_CACHED, &xtal_hz);
    if (ret != ESP_OK || xtal_hz == 0U) {
        // 查询失败时按 S31 的 40MHz 晶振经验值兜底。
        xtal_hz = 40000000U;
    }
    return (double)xtal_hz <= (double)mclk_hz * 1.99;
}
```

2. 在 `i2s_std_config_t std_cfg` 的聚合初始化之后（`i2s_output.c:83` 之后、`i2s_channel_init_std_mode` 之前）加入覆盖：

```c
    if (i2s_output_should_use_apll(sample_rate_hz)) {
        std_cfg.clk_cfg.clk_src = I2S_CLK_SRC_APLL;
        ESP_LOGI(TAG, "高采样率 %luHz：I2S 时钟源切换为 APLL（XTAL %luHz 无法满足 mclk 需求）",
            (unsigned long)sample_rate_hz, (unsigned long)xtal_hz);
    }
```

> 说明：XTAL 频率值可在判断函数内通过输出参数带回，避免重复查询；实现时用一个局部变量保存即可，不必再查两次。

3. 头文件依赖：新增 `#include "esp_clk_tree.h"`（`esp_hw_support` 公共头，`esp_driver_i2s` 已依赖该组件，无需改 CMake）。

4. **不改动** `audio_rate_profile.h`、`i2s_dma_desc_num`、DMA 帧数、GPIO 配置；不引入新的 fallback 分支（XTAL 路径对高采样率本来就不可能成功，重试无意义）。

## 为什么不用“降低 mclk_multiple”方案

- 降到 128 只能救 96k；176.4k/192k 仍失败（`40MHz > 1.99×rate×128` → `rate < 156.9kHz`，176.4k 刚好失败）。
- 降到 64 会让 master 的 `bclk_div = mclk/bclk` 变成 1，硬件分频不安全。
- APLL 能一次性覆盖全部档位，且 mclk 精确等于 `rate × 256`，bclk 分频为整数 4，音质与现有 44.1/48k 一致。

## 验证方式

1. 编译：在 `D:\ESP32\FakePod_S31` 执行 `pio run -e fakepod_s31`。
2. 烧录：`pio run -e fakepod_s31 -t upload`。
3. 让用户播放那条 96kHz FLAC（`/sdcard/MUSIC/Craig David - 7 Days.flac`），确认日志变为：
   - `I (…) I2S: Music I2S DMA档：desc=26 frames=256`
   - `I (…) I2S: 高采样率 96000Hz：I2S 时钟源切换为 APLL…`
   - `I (…) I2S: I2S TX 初始化成功：BCLK=6144000Hz，LRCK=96000Hz`
   - 后续出现 PCM 链路开启/播放正常日志，**不再出现** `sample rate is too large`。
4. 回归：连续切换 44.1k / 48k 普通曲目，确认仍走 XTAL、无新增日志、播放正常；再切回 96k 确认 APLL 与 XTAL 交替重建通道无异常（现有流程每次换曲都会 `i2s_output_stop()` 后重建，APLL 引用计数由驱动释放）。
5. 若设备上有 88.2k 或 176.4k 素材，顺带验证对应档位。

## 风险与遗留

- APLL 是全局音频 PLL，若后续其它外设（如 PDM/ADC）也占用 APLL 需协调；当前工程无其它 APLL 使用者（已全工程搜索确认无 `clk_src/APLL` 相关代码）。
- 192kHz FLAC 仍由 `audio_rate_profile.h:75` 的 `flac_stage_enabled=false` 禁用，本次不改该策略。
- 本次只修时钟源，不涉及 PPA/JPEG（两者已由用户日志验证生效）。
