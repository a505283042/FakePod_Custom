# FakePod NAS 曲库管理工具使用说明

这份说明适用于当前的 Windows NAS 曲库管理器。日常更新歌曲只需要**扫描、必要时准备短 ID、发布索引**，不需要每次重新解析整个曲库，也不用将音乐复制到 ESP32。

## 一、开始前，先在 NAS 上做好设置

FakePod 从 NAS 读取歌曲，Windows 工具则负责维护曲库索引。为了让两者正常工作，NAS 需要开启 **SMB 文件共享、WebDAV 和 SSH**。这三项不是三个音乐库，它们访问的必须是同一份音乐文件。

以目前使用的目录为例：

```text
NAS 内部：/volume1/麦田广告/Music
Windows：\\192.168.1.105\麦田广告\Music
WebDAV：http://192.168.1.105:5005/麦田广告/Music
```

上面是本项目的示例地址。NAS IP、共享文件夹、数据卷和端口以实际设备为准；带中文的 WebDAV 地址由工具自动处理编码。**Music 是音乐根目录**，里面可以按歌手、语种等继续建文件夹，不必为了 FakePod 重排歌曲。

### 1. 开启 SMB，让 Windows 能访问音乐目录

在 NAS 管理页面启用 SMB（Windows 文件服务），确保共享文件夹 `麦田广告` 可以访问。Windows 文件资源管理器地址栏输入：

```text
\\192.168.1.105\麦田广告\Music
```

应当能看到 MP3、FLAC 等歌曲。用于运行管理器的 Windows/NAS 账户不仅要能读取歌曲，还要能在 Music 下创建并写入 `_FakePod`，因为索引、扫描缓存和增量准备脚本都存放在那里。**不要把整个共享目录设置成任何人可写**；按账户分配必要权限即可。如果 NAS 上原有 Music 位于别的数据卷，请记录实际位置，例如 `/volume2/…`。

### 2. 开启 WebDAV，让设备读取歌曲和索引

在 NAS 管理页面安装或启用 WebDAV 服务，并开启 **HTTP 5005**（本项目当前使用的端口）。为 FakePod 准备一个可读取 Music 的 NAS 账户，例如 `webdav`。此账户通常只需要读取权限，**不需要 NAS 管理员或写入权限**。

确认这个账户能够通过 WebDAV 访问以下位置：

```text
/麦田广告/Music/
/麦田广告/Music/_FakePod/music-index/
/麦田广告/Music/_FakePod/track/
```

后两项在首次建立索引和执行 SSH 准备后才会生成。请保证这些目录及对应文件对用于播放的账户可读。打开 WebDAV 服务并不代表所有子目录都已授权；如果歌词返回 `403`，应检查对应 HTTP 路径和读取权限。

**安全提醒：** HTTP 5005 下的 Basic 认证不加密。只在可信局域网使用，避免做路由器公网端口转发；以后若改为 HTTPS 5006，须另行确认固件 TLS 和内存兼容性。

### 3. 开启 SSH，供工具建立歌曲和歌词的短链接

在 NAS 管理页面启用 SSH，记下实际端口。工具当前默认显示 **33**，但这只是项目里的预填值，不是所有 NAS 的默认端口。SSH 用户必须有权限在 Music 内检查文件、执行 `ln` 建立硬链接，以及在 `_FakePod` 中写入标记和隔离旧链接。工具预填 `root`，只有 NAS 确实允许该账户登录时才可使用；不必为了这项功能长期开放 root 远程登录。

NAS 上还需要有 `/bin/sh`、`stat`、`ln`、`mv` 等基本命令。硬链接要求源文件与 `_FakePod/track` 在**同一个文件系统**；它不会复制一整份 MP3、FLAC 或 LRC。如果 NAS 返回 `Operation not permitted`、`Permission denied` 或跨文件系统错误，请先核对 SSH 权限和 Music 所在卷，不要反复执行或对整个目录使用 `chmod 777`。

完成设置后，平时只需在更新曲库时临时使用 SSH。可以按自己的安全管理习惯，在维护结束后关闭 SSH。

## 二、第一次使用 Windows 管理器

先在 Windows 安装 **Python 3**，并确认 Tkinter 可以使用。在项目目录双击：

```text
tools\nas\启动NAS曲库管理器.bat
```

这是分类后的实际启动入口；原 `tools/` 根目录下的兼容批处理已清理。

打开后，填写 NAS 地址、WebDAV 端口、WebDAV 用户名与密码，点击 **「连接并浏览文件夹」**。双击文件夹进入 `麦田广告`，再进入 `Music`，停在 **Music 文件夹本身**，点击 **「使用当前目录作为 Music」**。不要选某位歌手的子文件夹，也不要选择 `_FakePod`。

选择成功后，窗口会自动显示三种对应位置：WebDAV Music 路径、Windows SMB 路径和 NAS SSH 内部路径。请核对 NAS 数据卷：如果 Music 实际位于 `/volume2`，就把高级选项中预填的 `/volume1` 改成 `/volume2`；不要只凭能浏览文件夹就认定 SSH 路径正确。

随后点击 **「扫描并预览增量更新」**。第一次没有扫描缓存，工具会读取曲库元数据，时间可能较长；完成后只在 Windows 临时目录生成待发布索引，**还不会覆盖 NAS 正在使用的曲库**。检查歌曲数量和提示，再进行后续操作。

## 三、以后新增歌曲、修改标签或添加歌词，怎么更新

日常使用只需按下面的顺序操作。**先停止 FakePod 上正在播放的 NAS 音乐**，避免更新时与播放、曲库热重载互相影响。

**第一步：扫描变化。** 点击 **「扫描并预览增量更新」**。工具会检查歌曲文件的大小和修改时间，复用没有变化的元数据，只重新读取新增或修改的歌曲。看一眼“新增、修改、删除、复用”的数量是否符合预期。仅新增同名 LRC 或替换封面时，也应重新扫描以更新关联信息；通常不需要勾选「重建全部元数据缓存」。

**第二步：按提示决定是否点击 ①。** 如果扫描窗口提示需要准备音频或 LRC 短 ID，点击 **「① SSH 准备音频/LRC短 ID」**。工具会弹出 SSH 终端，输入 NAS SSH 密码，等到出现类似：

```text
FakePod incremental prepare OK; changed audio: 0; lyrics: 4156; marker: ...ok
```

这才算准备成功。它在 NAS 内创建或修复硬链接，**不复制音频或歌词内容**。同一目录下名称主干相同的 MP3 和 FLAC 可以共用一份 LRC 源文件，各自的短 ID 链接会指向这份歌词。如果扫描提示没有短 ID 变化，可以**直接跳过 ①**。

**第三步：发布索引。** 点击 **「② 验证后发布 V2 索引」**。按钮点下后，工具会在后台再次核对歌曲路径、文件数量、大小、修改时间及 SSH 准备标记；所以歌曲多时，**确认窗口不会立即弹出**。校验通过再确认发布。看到“发布成功”才算完成；工具会备份原来的索引，并在最后写入 Meta 作为更新标记。

**第四步：如有删除歌曲，再考虑 ③。** 只有报告明确列出已删除歌曲时，才需要在**发布后**选择 **「③ SSH 隔离删除的旧 ID（可选）」**。它将旧短链接移到 `_FakePod/quarantine-*`，不删除原始音乐文件。没有删歌就不用点。

**最后一步：让 FakePod 读取新索引。** 确认设备 Wi-Fi 和 NAS 配置正常，停止播放后进入 **设置 → 连接 → NAS更新**，手动同步；也可以重启设备，让其开机自动检查。**SSH ① 成功不等于 V2 已发布**；如果设备显示“已最新”，先检查 Windows 端是否确实执行了 ②。曲库驻留时等待安全空闲重载，不要强行在播放期间刷新。

## 四、设备上的 NAS 地址要与工具保持一致

目前的手机 NAS 配对会根据所填写的 **Music 根 URL** 自动生成索引和短 ID 地址。以当前目录为例，配置关系应该是：

```text
music_url=http://192.168.1.105:5005/%E9%BA%A6%E7%94%B0%E5%B9%BF%E5%91%8A/Music
base_url=http://192.168.1.105:5005/%E9%BA%A6%E7%94%B0%E5%B9%BF%E5%91%8A/Music/_FakePod/music-index
track_url=http://192.168.1.105:5005/%E9%BA%A6%E7%94%B0%E5%B9%BF%E5%91%8A/Music/_FakePod/track
```

通过设备 **设置 → 连接 → NAS配对** 和 Android APP 写入配置时，一般不必手工改这三个地址。6 位授权码有效 3 分钟，操作按手机页面提示完成。

**注意旧配置：** 以前的 HTTP 8080 和 `/web/music-index` 路径不适用于当前默认部署，因此工具目录已移除对应旧样例。现在索引发布到 `Music/_FakePod/music-index`；设备 `base_url` 必须指向通过 WebDAV 实际可访问的索引目录。只有你明确保留旧版部署时，才按旧版本文档核对配置。

## 五、遇到问题，先看这几个地方

| 现象 | 检查方法 |
|---|---|
| WebDAV 无法连接或无法浏览 | 核对 NAS IP、5005 端口、账号密码、共享目录读取权限；同一局域网测试 |
| Windows 扫描失败 | 在文件资源管理器确认能打开 `\\NAS\共享名\Music`，并且管理账户能读取歌曲 |
| SSH 显示 `Audio/LRC source missing` | 看输出中的 **SSH path**，检查 NAS 实际文件名大小写、卷号和路径；不要凭 Windows 大小写不敏感的显示推断 Linux 路径 |
| 同名 MP3、FLAC 只有一份歌词 | 正常；同目录同名主干可共用一份 `.lrc`，不需要复制另一份 |
| 歌曲能播但某首 LRC 返回 HTTP 403 | 分别测试歌词短 ID 的 HTTP 地址和 WebDAV 账号权限；不能据此判断歌词解析器坏了 |
| 点击②后等待很久才弹确认 | 正在执行发布前全曲库核验，观察进度，避免重复点击或关闭程序 |
| 设备显示“已最新”但曲库没变 | 先核对②是否发布成功、设备 `base_url` 是否指向新索引，然后停止播放再同步 |
| 扫描结果异常或文件被移动 | 不要勉强发布；先还原正确 Music 目录，再重新扫描 |

不确定文件是否能从 WebDAV 读取时，可以在 Windows PowerShell 使用 `curl.exe --basic -u "webdav"` 访问相应文件（系统会询问密码），检查 HTTP 状态码。索引 Meta 或歌词文件正常读取一般应为 `200`；若是 `401/403/404`，优先检查认证、权限或实际路径。**不要把 NAS 密码写进截图、日志或发给他人。**

## 六、平时维护记住三句话

**新增或修改：先扫描；需要短 ID 才做①；最后一定做②。**

**删除歌曲：先发布新索引，需要时再用③隔离旧链接。**

**不需要每次全量重建，也不要手动删除 `_FakePod` 里的索引、缓存和短 ID。** 旧索引备份会保存在同一 `_FakePod` 目录内的 `backup-index-*` 中。若之后要重新迁移 NAS，请先备份 Music 和 `_FakePod`，再核对 WebDAV、SMB、SSH 三条路径。

---

本说明根据当前 `tools/nas/fakepod_nas_manager_gui.py`、索引生成器和设备 NAS 配对代码编写。NAS 管理页面名称可能随型号及 DSM 版本不同；优先按实际界面找到对应的 SMB、WebDAV、SSH 服务开关与权限设置。
