# FFmpeg MJPEG GUI v4 — FakePod 视频转换工具

把普通视频（mp4 / mkv / mov / avi / webm 等）转换为 FakePod 支持的 **AVI + MJPEG + MP3** 格式，输出适配 460×460 屏幕，支持竖版视频与正方形成片。

## 运行环境（必需）

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（Windows 7 需 .NET Framework 4.x） |
| PowerShell | 5.1 或更高，Windows 自带，无需安装（可在开始菜单搜 `powershell` 验证） |
| FFmpeg | **必需**，需安装并加入 PATH，使 `ffmpeg -version` 在 PowerShell 中可运行 |
| 权限 | 无需管理员权限 |

### 安装 FFmpeg（首次使用）

1. 从 FFmpeg 官网或 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 下载 Windows 构建版（选 full build 即可）
2. 解压到任意目录（如 `C:\ffmpeg`）
3. 把 `C:\ffmpeg\bin` 加入系统环境变量 **Path**（此电脑 → 属性 → 高级系统设置 → 环境变量）
4. 重新打开 PowerShell，输入 `ffmpeg -version` 能输出版本信息即成功

> 本工具需要 `ffmpeg.exe`，**不需要 ffprobe**（视频时长直接用 `ffmpeg -i` 解析）。索引扫描组件 `SidecarIndexGenerator.cs` 必须与 `app.ps1` 放在同一目录；Windows PowerShell 5.1 使用系统 .NET Framework 的 `Add-Type` 加载，无需另装编译工具。

## 使用方法

### 启动

双击 `start.bat` 即可（等价于用 PowerShell 执行 `app.ps1`）。窗口固定大小、不可缩放。

### 转换流程

1. 点击 **"选择…"** 选择输入视频（**可多选**：按住 Ctrl 逐个点选，或按住 Shift 连选一段）
2. 在 **"输出目录"** 中选择转换结果保存位置（默认使用第一个源视频所在目录；可点“选择目录…”更改，也可点“源目录”恢复）
   - 单文件和批量转换均使用同一个目标文件夹；所有 AVI 和对应 `.fvix` 索引集中保存在该目录
3. 按需调整视频 / 音频参数（批量时所有文件共用同一套参数）
4. （可选）点击 **"自动检测黑边"** 自动裁剪上下/左右黑边（仅对第一个选中的视频采样）
5. （可选）勾选 **"方形裁切 460×460"** 输出纯正方形画面
6. （可选）在 **"片头/片尾裁剪"** 填入要去掉的秒数，点 **"预览去头尾"** 核对边界后转换
   - 批量模式下按**每个文件自身时长**计算裁剪，超出时长的文件会被跳过并计入失败明细
7. 点击 **"开始转换"**，逐个转换并在后台生成 `.fvix` 索引：
   - 单个文件：完成后弹窗显示输出路径
   - 多个文件：完成后弹窗汇总“成功 / 失败”数量与失败明细；状态栏实时显示 `正在转换 (i/N)`；生成索引时显示扫描进度，不阻塞窗口操作消息
8. 界面底部会实时显示当前文件实际执行的 FFmpeg 命令（批量时为第一个文件的命令示例）

## 参数说明

### 视频参数

- **长边长度**：缩放目标（默认 460）。横版视频 → 宽 = 460；竖版视频 → 高 = 460，等比缩放、另一边自动取偶数
- **帧率 FPS**：默认 24；勾选方形裁切自动切为 20，取消勾选自动恢复 24
- **MJPEG q**：JPEG 质量（2 = 最清晰，31 = 最差），默认 5，越小越清晰、文件越大
- **使用裁剪参数**：手动裁剪黑边，格式 `crop=宽:高:X:Y`
- **自动检测黑边**：自动分析视频并填入裁剪参数（采样多段取多数结果，更可靠）
- **方形裁切 460×460**：先裁黑边，再把短边放大到 460、长边两侧居中裁掉，输出纯正方形画面；勾选自动采用 20FPS / q=5
- **片头/片尾裁剪**：去掉开头/结尾指定秒数（毫秒精度，如 `1.250` 秒）；点"预览去头尾"可拖动进度条查看任意位置画面，用"设为片头 / 设为片尾"直观选择边界，确定后自动回填数值；去片尾时自动探测视频时长。批量模式下预览只针对第一个文件，其余文件按各自时长套用相同秒数
- **强制 yuvj420p**：4:2:0 采样，老设备兼容，默认开启

### 音频参数（MP3）

- **码率**：96k ~ 320k，默认 192k
- **采样率**：保持默认 / 44100 / 48000
- **声道**：保持默认 / 单声道 / 双声道

## 批量转换

- 输入框一次可选中多个视频（Ctrl / Shift 多选），选中后状态栏显示 `已选择 N 个视频`
- 所有文件共用当前参数（分辨率、帧率、质量、码率、裁切、片头片尾）
- 输出位置：用户选择的统一目标目录；单文件和批量转换均使用该目录
- 命名规则：`源文件名_FP.avi`；同一批次出现重名时自动追加 ` (2)`、` (3)` 等序号，避免批次内部互相覆盖
- 逐个串行转换，同一时刻只运行一个 FFmpeg 进程；每个文件成功后自动生成同名 `.fvix` V2 索引
- 中途某个文件失败不会中断整批，结束时汇总失败原因；可把界面里的命令复制到 PowerShell 单独排查

## 默认转换参数

- 容器 AVI，视频 MJPEG，音频 MP3
- 长边 460、24 FPS、MJPEG q=5、MP3 192k、yuvj420p
- 可自动检测黑边
- 可选方形裁切 460×460（勾选自动切为 20FPS / q=5）
- 转换成功自动在后台生成同名 `.fvix` V2 侧车索引（设备端任意位置 SEEK 用；失败不影响播放）；单独补生成索引也在后台执行，窗口显示扫描百分比、已扫描 MB 和索引点数量
- V2 索引每约 2 秒记录视频帧序号、视频 chunk 偏移和此前累计的 MP3 字节数；同时保存 AVI 文件长度及抽样 CRC32，设备端加载时会核对来源
- 设备端最多加载 100,000 条索引；10 小时视频约占 288 KB PSRAM，2 秒粒度可覆盖约 55.5 小时
- 旧版 V1 索引仍可读取，但没有来源指纹和累计音频字节锚点；建议用本工具的“生成 .fvix 索引”功能为旧 AVI 重新生成 V2 索引
- 对超过单个 RIFF 段容量的 OpenDML AVI，设备端和索引工具会继续读取后续 `RIFF AVIX` 段；生成/加载的 V2 索引覆盖全部 `movi` 区间
- 设备端视频 I/O 使用 FatFs 原生 `FIL` / `f_read` / `f_lseek`，不再经过 32 位有符号 `off_t`；FAT32 卡上的单个 AVI 支持超过 2GB，当前设备端与 V2 索引偏移上限为 4GB（文件长度必须小于 `4,294,967,296` 字节）。
- 当前固件未启用 exFAT；超过 4GB 的单个视频文件暂不支持，不能仅靠把文件偏移改成 64 位解决。
- 若 AVI 已有旧版 V2 索引且只覆盖第一个 `movi` 段，设备端会拒绝该不完整索引（不影响顺序播放）；请重新点击“生成 .fvix 索引(可多选)”

## 常见问题

| 问题 | 解决 |
|---|---|
| 提示"未检测到 FFmpeg" | 安装 FFmpeg 并加入 PATH，重开工具 |
| 转换失败 | 把界面中"实际 FFmpeg 命令"复制到 PowerShell 手动执行，查看详细错误 |
| 竖版视频怎么转 | 默认模式输出宽 460 的竖幅；需要正方形成片就勾选"方形裁切" |
| 窗口打不开 / 无界面 | 确认系统 PowerShell 5.1 可用（`powershell.exe`） |
| 批量时某个文件失败 | 看结束弹窗的失败明细；界面底部命令框显示的是当前文件的命令，复制到 PowerShell 可看 FFmpeg 详细报错 |
| 批量输出在哪 | 所有转换结果统一保存在界面选择的“输出目录”；点“打开输出目录”即可查看 |

## 其他说明

- 纯本地转换，不联网，不上传任何文件
- 脚本为 UTF-8 带 BOM 编码，兼容中文 Windows 的 PowerShell 5.1
- 输出文件请放入 TF 卡的 `video` 文件夹供 FakePod 播放


## 索引生成性能说明

- `.fvix` V2 扫描器使用独立的 C# 实现和 1MB 顺序读取缓存，避免 PowerShell 对每个 AVI Chunk 反复创建小字节数组、设置文件位置。
- 扫描器按文件顺序读取 Chunk Header；跳过 JPEG/MP3 Payload 时只移动逻辑偏移，跨出缓存窗口后才进行底层文件读取。
- 手动补生成索引和转换完成后的自动索引均通过后台线程执行；界面持续响应，进度条显示扫描进度、已扫描数据量、视频帧数和索引点数量。
- 索引格式仍为 FVIX V2：2 秒粒度、16 字节条目、文件长度和抽样 CRC32 校验；不改变设备端索引兼容性。
- 单文件偏移范围仍小于 4GB；本次优化不改变 FAT32 / FVIX V2 的容量边界。
